## 1. 動的中央値管理とデータ構造の選択
クエリごとに要素が追加される中で、常にソートされた状態を保ち「中央値」を高速に取得する問題を通して、C++のデータ構造（`vector` と `multiset`）の内部挙動と計算量の違いについて学びました。

### ① `vector::insert` によるアプローチ（TLE）
* **解法イメージ**: 綺麗に並んでいる `vector` に対して、新しく入る数字の正しい位置を `lower_bound`（二分探索）で高速に見つけ、`v.insert()` で割り込ませる方法。
* **課題点（なぜ TLE になるのか？）**: 
  * **割り込み処理の仕組み**: `vector` はメモリ上に一列に隙間なく要素が並ぶため、途中に要素を1個割り込ませると、それ以降の要素全員が1マスずつ後ろにズレる（席替え）必要がある。
  * **計算量**: 位置を見つける（二分探索）のは $O(\log N)$ だが、席替え（要素の移動）に最悪 $O(N)$ かかる。クエリ数を $Q$ とすると、全体で **$O(Q^2)$** となり、要素数が10万件などの場合に制限時間（2秒）を超えてしまう。

### ② `multiset` ＋ しおり（イテレータ）大作戦（AC）
* **解法イメージ**: 常に自動で中身をソートされた状態にキープしてくれる `std::multiset` を使用。「何番目」というインデックス指定ができない代わりに、今の中央値を指す **「しおり（イテレータ）」** を1本用意し、新しく追加される2つの数字と見比べながら手動で左右に1歩ずつ動かす。

```cpp
// 常に真ん中を指すしおり（mid）を動かすロジック
st.insert(a[i]);
st.insert(b[i]);

if (a[i] < *mid && b[i] < *mid) {
    mid--; // 両方小さければ真ん中は左に1歩ズレる
} else if (a[i] >= *mid && b[i] >= *mid) {
    mid++; // 両方大きければ真ん中は右に1歩ズレる
}
// 片方ずつならバランスが取れるので mid は動かさない
```

* **なぜ爆速（AC）になるのか？**: 
  * `multiset` の内部は一列ではなく **「木構造（ツリー構造）」** でデータを持っている。
  * 新しい要素を追加するとき、周りの数字を1ミリも動かさず、空いている隙間にポインタを繋ぎ替えて「スポッとはめる」だけなので、追加処理が $O(\log N)$ で終わる。中央値の更新も、しおりを1歩動かすだけ（$O(1)$）。
  * 全体の計算量は **$O(Q \log N)$** となり、10万件のクエリも0.1秒未満で処理できる。

### ③ 「裏側はただの木」？自作への展望と罠
`multiset` の挙動を理解すると「自分でも木構造を実装できるのではないか」という結論に至るが、自作する際には大きな罠（偏りの問題）が存在する。
* **単純な二分探索木の限界（棒になる罠）**: 例えば、`1, 2, 3, 4, 5...` と綺麗にソートされた順にデータを単純な木に `insert` していくと、木が枝分かれせず、右下にひたすら長く伸びる「一本の棒」になってしまう。こうなると、最悪計算量が $O(N)$ に退化して `vector` と変わらなくなってしまう。
* **`multiset` の本当の正体**: C++の `multiset` は、裏側で **「自己平衡二分探索木（主に赤黒木：Red-Black Tree）」** という高度な仕組みが採用されている。これは、要素が追加されて左右のバランスが崩れそうになった際、木を自動的に回転させて綺麗な形にリフォームする機能を持っている。

## 2. C++ 基礎編

### ① 型の演算と連結
C++では、型の組み合わせによって挙動が変わるため注意必要。

| 組み合わせ | 挙動 | 備考 |
| :--- | :--- | :--- |
| `char` + `char` | **数値計算** | 文字コード（ASCII）としての足し算になる |
| `char` + `string` | **連結** | 文字列の末尾に文字が追加される |
| `string` + `string` | **連結** | 文字列同士がつながる |

### ② ループの制御 (`break`)
* **二重ループの注意点**: `break` は **現在実行中のループ（一番内側）** しか抜けない。
* 外側のループまで一気に抜けたい場合は、フラグ（`bool`）を使うか、関数にして `return` するのが一般的。

### ③ 二次元配列 (`vector<vector<T>>`)
2次元配列は「配列の配列」という構造であることを意識する。
* **行数（タテ）**: `vec.size()`
* **列数（ヨコ）**: `vec[0].size()` （0番目の行に含まれる要素数）
* **アクセス**: `vec[i][j]` （i行目のj列目）

### ④ 表形式の出力（改行と空白の制御）
行末に余計な空白を入れないための実装パターン。競技プログラミングの出力形式指定で多用する。

```cpp
for (int i = 0; i < N; i++) {
    for (int j = 0; j < N; j++) {
        cout << table[i][j];

        if (j == N - 1) {
            cout << endl; // 行末なら改行
        } else {
            cout << " ";  // 要素間なら空白を入れる
        }
    }
}
```
